# NewLife.NovaDb 存储架构

> 对应模块：S01-S06（Storage 领域）
> 关联模块：L01-L05（WAL/Binlog）、N02/N05（索引冷热分离 → 见[索引架构.md](索引架构.md)）

---

## 1. 设计目标

| 目标 | 说明 |
|------|------|
| 文件夹即数据库 | 一个目录 = 一个数据库，拷贝即迁移 |
| 每表独立文件组 | 表间 IO 与锁完全隔离，单个文件可独立删除/移走 |
| MMF 驱动 | 64 位虚拟地址空间 128TB，OS 按需映射；索引与行载荷都不常驻托管堆 |
| 单文件可移除 | 运维可直接清理某个索引或数据文件，引擎按文件角色降级后继续服务 |
| 纯托管 | 无 Native 依赖，全 C# 实现 |

## 2. 数据库目录结构

### 2.1 文件分类

**数据库级文件**：

| 文件 | 说明 |
|------|------|
| `nova.db` | 库级文件头（32 字节），标记目录为 Nova 数据库 |
| `nova.{SeqNo:D6}.binlog` | 逻辑日志（网络模式，按文件滚动） |

**表级文件组**（全部平铺在数据库目录下）：

| 后缀 | 角色 | 说明 |
|------|------|------|
| `.schema` | 表结构 | JSON 格式，SQL 引擎启动时据此打开表 |
| `.rlog` | 行数据 | 只追加的 Put/Delete 记录，载荷按偏移读取 |
| `.hidx` | 主键哈希字典 | MMF：桶数组 + 键节点 + 值链，等值点查 O(1) |
| `.oidx` | 主键有序段 | 追加式有序 run，范围 / `ORDER BY` / 全表顺序扫描 |
| `{表}_{索引}.hidx` | 二级索引哈希字典 | 等值、`IN`、唯一性检查、索引计数 |
| `{表}_{索引}.idx` | 二级索引全量基线 | 旧格式，作为 `.hidx` 的重建来源 |
| `{表}_{索引}.idxl` | 二级索引增量日志 | 提交时追加 Put/Delete |
| `.wal` | 预写日志 | 崩溃恢复 |

> `.data` 已停止创建；旧版本数据库中的 `.data` 仍可被识别，但 Nova 表的数据实际写在 `.rlog`。

### 2.2 文件命名

| 文件类型 | 命名 |
|---------|------|
| 行数据 / 表结构 | `{Table}.rlog` / `{Table}.schema` |
| 主键索引 | `{Table}.hidx` / `{Table}.oidx` |
| 二级索引 | `{Table}_{Index}.hidx` / `.idx` / `.idxl` |
| WAL | `{Table}.wal` |

### 2.3 目录示例

```
StarDust/                          ← 文件夹即数据库
├── nova.db                        ← 库级文件头
├── nova.000001.binlog             ← Binlog（网络模式）
│
├── User.schema                    ← 表结构
├── User.rlog                      ← 行数据
├── User.hidx / User.oidx          ← 主键索引
├── User_Name.hidx                 ← 二级索引哈希字典
├── User_Name.idx / .idxl          ← 二级索引基线与增量
├── User.wal
│
├── App.schema / App.rlog / App.hidx / App.oidx / App.wal
└── flux.rlog / flux.col           ← Flux 引擎（不作为独立表列出）
```

## 3. 文件格式

### 3.1 公共文件头（FileHeader，32 字节）

`nova.db`、`.hidx`、`.oidx`、`.idx`、`.wal` 共用统一文件头：

```
偏移  大小  字段            说明
0     4B   Magic           0x4E4F5641 ("NOVA")
4     1B   Version         格式版本（当前 1）
5     1B   FileType        1=Data 2=Index 3=Wal 4=Binlog 5=Metadata
6     1B   PageSizeShift   页大小 = 1 << shift
7     1B   Flags           bit0=加密 bit1=压缩 bit2=只读
8     8B   CreateTime      UTC 毫秒
16    12B  Reserved        填零
28    4B   Checksum        CRC32（覆盖 0-27）
```

校验：读取时重新计算 CRC32 并比对，不一致则文件损坏。

### 3.2 库级文件（nova.db）

```
nova.db:
└── FileHeader (32B)   ← 标记目录为 Nova 数据库，并记录版本与页大小
```

表结构单独落在每张表的 `{Table}.schema`（JSON）：

```
{Table}.schema:
└── TableSchema { TableName, Comment, EngineName, Columns[], Indexes[] }
```

**修改机制**：先写临时文件，完成后原子重命名，保证崩溃安全。表在启动时按 `.schema` 逐个打开，`.rlog` 缺失不影响其他表。

### 3.3 行日志（.rlog）

```
[FileHeader 32B]（魔数 NRLG，Version=1）
[RecordLength: 4B][RecordType: 1B][Data: N][Checksum: 4B] ...
```

- `RecordType=1`（Put）：`Data` 为整行序列化载荷，主键从中提取。
- `RecordType=2`（Delete）：`Data` 为主键编码。
- `Checksum` 为 `RecordType + Data` 的 CRC32。
- 记录只追加，载荷偏移固定，因此行版本只需保存（偏移，长度）。

列编码规则由 `IDataCodec` 定义，NULL 用长度 1 且内容 0x00 表示。

### 3.4 索引文件

主键与二级索引的文件布局见[索引架构.md](索引架构.md) §4、§5。

## 4. 行载荷读取（RowStore）

`RowStore` 把整份 `.rlog` 映射一次，按需读取：

- 写入走 `FileStream` 顺序追加，提交时统一刷新一次。
- 读取走 `MemoryMappedViewAccessor`，只有访问过的页占用物理内存，内存紧张时由 OS 回收。
- 文件增长后重建映射；`TRUNCATE`/压缩替换文件前先 `Reset()`（Windows 有映射视图时不能缩短文件）。

内存占用：行版本只保留 `DataOffset`/`DataLength`，不保留 `Byte[]` 载荷。

---

## 5. MMF 分页访问器（MmfPager）

利用 `MemoryMappedFile`，64 位系统 OS 仅映射实际访问的页到物理内存。

```
物理内存（有限）            虚拟地址空间（128TB）
┌──────────┐             ┌─────────────────┐
│ 热点页面  │ ←─ 映射 ── │  Page 3 (热)    │
│ Page 3   │             │  Page 7 (热)    │
│ Page 7   │             │  Page 12 (热)   │
└──────────┘             │  Page N ← OS 按需加载
                         └─────────────────┘
```

核心能力：

- 自动写入/验证 FileHeader
- `ReadPage(pageId)` / `WritePage(pageId, data)` 随机读写
- 可选 CRC32 校验
- 写入超范围时自动扩展文件
- 线程安全（内部锁保护）

配置：`PageSize`=4096、`EnableChecksum`=true、`PageCacheSize`=1024。

> 该工具保留给页式访问场景，**不在 Nova 表主路径上使用**：行数据走 `.rlog` + `RowStore`，索引走 `.hidx`/`.oidx`。

---

## 6. 页面缓存（PageCache）

基于 `LinkedList + Dictionary` 的 O(1) LRU，配套 `MmfPager` 使用：

- **TryGet**：命中移至头部
- **Put**：满时淘汰尾部，新页插入头部
- **监控**：HitCount / MissCount / Count / Capacity

## 7. 并发控制

| 模式 | 引擎并发 | 跨进程锁 | 说明 |
|------|---------|---------|------|
| 嵌入 | MVCC（进程内） | 表级文件锁 | 一写多读，表间互不影响 |
| 服务器 | MVCC | 无（单进程） | SqlEngine 统一调度 |
| 只读 | 只读 | 无 | 多进程可同时读；只读模式不做文件降级 |

## 8. 存储配置汇总

### 8.1 DbOptions（嵌入 + 服务器共用）

| 配置项 | 默认值 | 说明 |
|--------|-------|------|
| Path | — | 数据库目录 |

## 9. CRUD 数据流（存储视角）

### 写入

```
Insert/Update/Delete → 写集（内存）→ COMMIT
  → 追加 .rlog 记录 → 应用主键 .hidx/.oidx → 应用二级 .hidx → 追加 .idxl
  → 刷行日志 → 刷索引元数据
```

### 读取

```
Get → 写集查未提交 → .hidx 桶定位 → 版本链取存活版本
    → RowStore 按（偏移, 长度）映射读取 → MVCC 可见性 → 反序列化
```

### 运维清理

```
删除/移走某个文件 → 下次巡检（默认 200ms）发现路径消失 → 按文件角色降级
```

### Checkpoint

```
后台线程 → 扫描 WAL 记录 → 行日志与索引已落盘 → 删除/截断 .wal
```

## 10. 文件级在线移除与降级（S07）

### 10.1 运维操作约定

| 平台 | 操作 | 说明 |
|------|------|------|
| Linux | `rm 文件` | 已打开的文件被 unlink 后仍可读，引擎释放句柄后空间回收 |
| Windows | `move 文件 别处` | 有映射视图时 `DeleteFile` 被拒（ERROR_USER_MAPPED_FILE），但带 `FileShare.Delete` 的句柄允许改名 |

所有长生命周期文件以 `FileShare.Read | FileShare.Delete` 打开，因此 Windows 上也可以直接移走被占用的文件。

### 10.2 降级语义

| 被移除文件 | 引擎行为 | 数据影响 |
|-----------|---------|---------|
| `{表}_{索引}.hidx` | 注销该索引，查询回退全表扫描，重启后自动重建 | 数据完整，唯一约束在降级期间不生效 |
| `{表}.hidx` / `{表}.oidx` | 立即按行日志整表重建，重建期间阻塞该表访问 | 数据完整 |
| `{表}.rlog` | 视为空表：重建空日志，重置主键与二级索引，清空未提交写集 | 该表数据丢失（运维主动清理的语义） |
| `{表}_{索引}.idx` / `.idxl` | 运行期不读取，删除无影响 | 下次启动 `.hidx` 已对齐时不需要基线 |
| `{表}.wal` | 重建 WAL 文件 | 已提交数据在 `.rlog`，仅丢失崩溃恢复日志 |

### 10.3 可见性

`SELECT * FROM _sys.table_files` 返回每张表的文件清单：

| 列 | 说明 |
|----|------|
| `table_name` | 表名 |
| `file_name` | 文件名 |
| `role` | `data` / `primary_hash` / `primary_order` / `secondary_index` / `index_baseline` / `index_delta` / `schema` / `wal` |
| `exists` | 文件当前是否存在 |
| `size` | 文件字节数 |
| `degraded` | 是否处于降级状态 |

### 10.4 已知限制

- 巡检有间隔（默认 200ms），窗口内的写入可能落到已被移走的文件；可配置为 0 换取即时检测。
- 主键索引重建期间该表不可用，代价与表行数成正比。
- 先移走文件、又在原路径新建同名文件的场景不会被视为替换（引擎继续使用原句柄）。
- 只读模式不修改磁盘，也不做降级检测。

## 11. 设计决策

| # | 决策 | 要点 |
|---|------|------|
| D1 | 纯托管实现 | 无 native 依赖，跨平台一致 |
| D2 | MMF 存储 | 利用 OS 虚拟内存，128TB 地址空间；索引与载荷均按需装入 |
| D3 | 表级 WAL | 独立 WAL 减少竞争，简化恢复 |
| D4 | Nova 不分片 | 单表多文件，MMF 高效处理超大文件 |
| D5 | 行日志即表数据 | `.rlog` 是唯一事实源；`.data` 仅为旧库兼容 |
| D6 | Binlog 独立于 WAL | 职责正交，互不依赖 |
| D7 | Binlog 可手工删除 | 文件自包含，删除不导致崩溃 |
| D8 | 单文件可移除 | 按文件角色分级降级；句柄带 `FileShare.Delete`，见架构设计 D20 |
