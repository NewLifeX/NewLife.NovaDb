# 多语言本地化

> 基线：NewLife.Core 12（31 种内置语言）编译期词表｜本库运行时 11 种语言｜英文为源文与兜底

## 1. 语言分层

本库按 NuGet 下载量分层维护运行时词表：下载量较高的核心组件对齐 NewLife.Core 的 31 种语言，其余组件维护 11 种语言（与 README 读者一致）。NovaDb 属于生态中的数据库类库、不在 31 语种核心组件清单内，按 **11 种语言**维护：英文源文 + 10 份译文。缺失译文在运行时自动回退英文，新增语言不需要改代码。

词表文件（10 个，另有英文源文兜底）：

- zh-Hans
- zh-Hant
- es
- de
- ja
- fr
- pt
- ru
- ko
- ar

> 语言档位由生态角色决定，不随 README 数量变化：核心类库（Core/Remoting/Agent/XCode/Redis/Stardust/AI/IoT）31 种；其它发布 NuGet 的生态类库至少 11 种；Web 产品只要求魔方与 ZeroIoT 主站。NovaDb 保持 11 种。

## 2. 词表文件

- `NewLife.NovaDb/Locales`

- 文件名即 BCP 47 语言代码；英文是源文与兜底，**不需要** `en.yml`。
- 键为**英文原文**，必须与代码字符串逐字一致（含空格与标点）；占位符 `{0}` 与格式说明符 `{1:n0}` 必须与英文一致。
- 词表由 NewLife.Core 包内的源生成器在编译期读取并生成压缩语言表，NativeAOT 下同样可用。
- 源生成器自动注册按程序集类型区分覆盖优先级：可执行程序集默认 `overwrite=true`，类库默认 `false`。NovaDb 作为类库只补充新 key，Core 同名 key 仍优先；需要覆盖时在工程中设置 `NewLifeLocalizationOverwrite=true`。

### 2.1 宿主语言与请求语言

NovaDb 本身是 TCP 服务端，不直接依赖 HTTP；嵌入 Web 应用时可复用 Core 的请求语言能力：

- `Localization.Culture`：强制异常与常规文本语言。
- `Localization.LogCulture`：日志与配置注释语言；为空时跟随 `Culture`，两者都为空时日志跟随 `CurrentUICulture`、配置注释输出英文源文。
- `NewLife.RequestCultureScope.Create(acceptLanguage)`：按 `Accept-Language` 的 q 权重选择最高权重且存在译文表的语言；只修改 `CurrentUICulture`，释放时还原。
- `Localization.IsSupported(culture)`：判断某区域性是否存在译文表，支持 `fr-CA → fr`、`zh-CN → zh-Hans`、`zh-TW → zh-Hant` 的父级匹配。

> 下游不要自行复制 `RequestCultureScope` 实现，直接使用 `NewLife.Core` 中的 `NewLife.RequestCultureScope`。

**服务端语言策略**：服务端异常文本跟随进程的 `Localization.Culture`（默认 `CurrentUICulture`）。需要稳定英文协议的部署，应在启动时显式设置 `Localization.Culture = CultureInfo.GetCultureInfo("en")`；客户端判断错误应以 `ErrorCode` 为准，不依赖文本。

## 3. 代码写法

| 场景 | 写法 | 是否自动翻译 |
|------|------|:------------:|
| `NovaException` | `throw new NovaException(ErrorCode.X, "Session {0} is closed.", sessionId);` | ✅ 构造器翻译 |
| BCL 异常 | `throw new InvalidOperationException(L.T("Session {0} is closed.", sessionId));` | ❌ 调用点显式 |
| 日志 | `Log?.Warn("Replication to slave {0} failed: {1}", node, ex.Message);` | ✅ `Logger.Format` |
| 手工拼接日志片段 | `L.TLog("Session {0} is closed.", sessionId)` | ✅ 日志语言入口 |
| 带实例前缀日志 | `Log?.InfoPrefixed(prefix, format, args)` | ✅ 前缀不参与查表 |
| 返回给调用方的文本 | `L.T("Database '{0}' does not exist.", name)` | ❌ 调用点显式 |

**硬规则**：

1. 一次性消息禁止字符串插值（`$"..."`），必须用格式字符串 + 参数；否则模板已展开，无法再按原文查表。
2. 模板按**整句**查表，参数本身不翻译；不要把英文状态词塞进 `{n}`，应按语义拆成完整句子。
3. 实例前缀在翻译之后拼接；`InfoPrefixed` / `ErrorPrefixed` / `WritePrefixed` 已处理。
4. 同一句英文在不同语境语义不同时，改写为语境明确的完整句子，避免一条键承担多种含义。
5. 修改英文源文等于修改 key：必须同批更新全部词表，不能让旧键变成孤儿。
6. 异常消息只翻译自然语言，错误码、协议字段、SQL 关键字、类型名、文件扩展名、品牌名保持原样。

## 4. 新增一条消息

1. 代码中写英文源文：`throw new NovaException(ErrorCode.SessionClosed, "Session {0} is closed.", sessionId);`；日志直接写英文模板。
2. 在全部语言文件的同一位置补齐该键；遗漏只回退英文，不会编译失败。
3. 运行校验脚本确认键集合、占位符与格式说明符一致。

### 4.1 不翻译清单

- 品牌与产品名：`NewLife`、`NovaDb`、`XCode`、`Cube`、`Stardust`、`NewLife.NovaDb Hybrid Database`
- 协议与存储标识：`ErrorCode` 名称、SQL 关键字、JSON 字段、日志前缀、文件扩展名（`.data`/`.idx`/`.wal`/`.kvd`/`.binlog`）
- 技术专名：`LZ4`、`MVCC`、`WAL`、`Binlog`、`Redis Stream`、`SkipList`、`BM25`
- 代码标识：类名、方法名、参数名、配置键、环境变量
- 代码注释与 XML 注释：开发者语言保持中文

### 4.2 术语统一

| 英文 | 简体中文 | 繁體中文 |
|------|----------|----------|
| database | 数据库 | 資料庫 |
| table | 表 | 資料表 |
| index | 索引 | 索引 |
| transaction | 事务 | 交易 |
| consumer group | 消费组 | 消費者群組 |
| replication | 复制 | 複寫 |
| shard | 分片 | 分片 |
| checkpoint | 检查点 | 檢查點 |
| recovery | 恢复 | 復原 |

其余语种沿用英文技术专名，只翻译自然语言；同一语种内保持同一术语，不混用同义词。

## 5. 校验

```powershell
# 运行时消息必须为英文（调用点不得含 CJK）
pwsh -File tools/check-english-exceptions.ps1 -Dir NewLife.NovaDb

# 词表一致性（默认允许未翻译占位回退英文）
pwsh -File tools/check-locales.ps1 -LocaleDir NewLife.NovaDb/Locales -SourceDir NewLife.NovaDb

# 全语言翻译完成后启用：禁止“值与英文源文相同”的占位
pwsh -File tools/check-locales.ps1 -LocaleDir NewLife.NovaDb/Locales -SourceDir NewLife.NovaDb -RequireTranslated
```

CI 的 localization job 会执行同一组脚本；源码中 `L.T`、`NovaException`、`XTrace.WriteLine`、`Log?.Xxx`、`WriteLog` 的字面量必须在基准词表中存在，否则视为“代码已本地化、词表漏条目”。

## 6. 程序集与 NuGet 元数据

- `AssemblyTitle` / `Description` 使用**英文源文**，并把同一字符串作为 key 写入 `Locales/*.yml`；反射展示处调用 `L.T(value)` 即可本地化。
- `PackageDescription` 允许中英混排，`Description` 保持纯英文供反射使用；`PackageTags` 保留中英关键词。
- `PackageReleaseNotes` 与版本号属发版流程专属字段，日常本地化提交不得改动。

## 7. 实施顺序

| 阶段 | 内容 | 完成标准 |

| P0 | 包升级、脚本入 `tools/`、CI 门禁、元数据英文化、规范文档 | 编译通过，CI 四道门禁可运行 |
